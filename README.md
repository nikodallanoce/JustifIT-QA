# JustifIT-QA Inference Pipeline

This repository contains the code used to reproduce the main inference pipeline described in the accompanying paper: retrieval-augmented legal answer generation, iterative answer refinement through a judge-based feedback loop, and verbatim evidence extraction from the retrieved statutory context.

## Overview

The pipeline is organized into two main scripts:

- `feedback_loop.py`: generates legal answers grounded in retrieved articles, iteratively refines them through a judge model, and evaluates the generated answers against expert-written answers.
- `generate_evidence.py`: takes the generated conversations and answers, then extracts verbatim supporting evidence from the retrieved legal texts.

At a high level, the workflow is the following:

1. Retrieve relevant legal articles from the JuriFindIT corpus.
2. Re-rank the retrieved articles with a Qwen reranker.
3. Generate an answer with an LLM conditioned on the retrieved context.
4. Verify the answer with a judge model and, if needed, refine it through iterative feedback.
5. Save the generated conversation history.
6. Use the saved conversation dataset to extract verbatim evidence spans for the generated answers.

## Script Details

### `feedback_loop.py`

This script implements the answer generation and refinement stage.

Main components:

- loads the `jurifindit/JuriFindIT` corpus and the `datasets/justifitqa.pkl` question dataset
- builds a dense retriever with `HuggingFaceEmbeddings`
- re-ranks retrieved documents with `Qwen3Reranker`
- generates an answer to each question using a legal prompting strategy
- verifies the answer through a judge prompt
- if the answer is not fully compliant, appends judge feedback to the conversation and generates a revised answer
- repeats the process for a fixed number of iterations
- saves:
  - the feedback-loop conversation dataset
  - an additional dataset containing the evaluation of generated answers against expert-labelled answers

In practice, this script is the main entry point for legal answer generation.

### `generate_evidence.py`

This script implements the evidence extraction stage.

Main components:

- loads the conversation dataset produced by `feedback_loop.py`
- extracts the assistant answers from the saved conversation history
- retrieves and re-ranks the relevant articles again
- prompts an LLM to extract only verbatim evidence spans supporting each generated answer
- stores:
  - the generated evidence for each answer
  - the retrieved article ids used for that question

This step is designed to produce text spans copied verbatim from the retrieved legal context, so that each generated answer can be inspected together with its textual support.

## Important Path Dependency

`generate_evidence.py` expects as input the conversation dataset generated by `feedback_loop.py`.

Therefore:

- `--feedback_ds_out_path` in `feedback_loop.py`
- **must be equal to**
- `--conversation_ds_path` in `generate_evidence.py`

For example, if you run:

```bash
python feedback_loop.py --feedback_ds_out_path datasets/feedback_loop_result
```

then you must later run:

```bash
python generate_evidence.py --conversation_ds_path datasets/feedback_loop_result
```

If these two paths do not match, `generate_evidence.py` will not be able to load the generated conversations.

## Example Usage

### 1. Run the feedback loop

This step generates grounded answers, refines them through judge feedback, and saves the conversation dataset.

```bash
python feedback_loop.py \
  --llm_model_repo Qwen/Qwen3-8B \
  --llm_verifier_repo Qwen/Qwen3-8B \
  --embedder_model_name retriever \
  --reranker_model_repo Qwen/Qwen3-Reranker-4B \
  --cache_dir /path/to/hf_cache \
  --cutoff_k 20 \
  --reranker_cutoff_k 4 \
  --reranker_bsz 4 \
  --retriever_bsz 16 \
  --feedback_loop_max_iters 3 \
  --feedback_ds_out_path datasets/feedback_loop_result \
  --labelled_answ_ds_out_path datasets/feedback_loop_result_w_answer_eval
```

Optional flags:

```bash
--use_thinking
--use_thinking_verif
```

Outputs:

- `datasets/feedback_loop_result`
- `datasets/feedback_loop_result_w_answer_eval`

### 2. Generate verbatim evidence

This step loads the saved conversations and extracts verbatim evidence spans for the generated answers.

```bash
python generate_evidence.py \
  --conversation_ds_path datasets/feedback_loop_result \
  --llm_model_repo Qwen/Qwen3-8B \
  --embedder_model_name justifit/DARv2 \
  --reranker_model_repo Qwen/Qwen3-Reranker-4B \
  --cache_dir /path/to/hf_cache \
  --cutoff_k 20 \
  --reranker_cutoff_k 4 \
  --reranker_bsz 4 \
  --retriever_bsz 16 \
  --output_path datasets/gen_evidence
```

Output:

- `datasets/gen_evidence`

Run the two scripts in sequence:

```bash
python feedback_loop.py \
  --llm_model_repo Qwen/Qwen3-8B \
  --llm_verifier_repo Qwen/Qwen3-8B \
  --embedder_model_name retriever \

  --cache_dir /path/to/hf_cache \
  --feedback_ds_out_path datasets/feedback_loop_result \
  --labelled_answ_ds_out_path datasets/feedback_loop_result_w_answer_eval

python generate_evidence.py \
  --conversation_ds_path datasets/feedback_loop_result \
  --llm_model_repo Qwen/Qwen3-8B \

  --reranker_model_repo Qwen/Qwen3-Reranker-4B \

```

## Notes

- `feedback_loop.py` performs both answer generation and comparison against expert answers.
- `generate_evidence.py` extracts evidence only after the feedback-loop conversations have already been saved.
- The path passed to `--feedback_ds_out_path` must coincide with the path passed to `--conversation_ds_path`.
- The retrieval pipeline is based on dense retrieval followed by re-ranking.
- The evidence extraction prompt is designed to return only JSON with verbatim citations.
